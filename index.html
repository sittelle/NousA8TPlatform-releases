Adopting a NOUS A8T

From a factory plug running Tasmota, to Rescue, to a working Charge Guard install. Every step happens in a browser — Tasmota's own page, then the device's own pages after that.

0

Before you touch the plug

Thirty seconds now saves a UART recovery session later.
  • You can reach the plug's IP address in a browser, on this computer or phone.
  • The plug is on stable mains power, with nothing plugged into the relay — a load that loses power mid-write is the one thing you can't undo.
  • You know the plug's current LAN address (check your router's device list, or Tasmota's own Information page).
One shotEvery upload below is deliberately a single attempt. If a result looks uncertain, stop and read it again before trying a second time — don't retry blind.
1

Adoption

Turns stock Tasmota into our own Rescue platform — two pages, no files to run.
  • Open http://<plug-ip>/up — Tasmota's own Firmware Upgrade page.
  • Choose NousA8TAdoption.bin and click Upgrade. Tasmota switches to Safe Boot and back on its own; just wait.
  • The device restarts running Adoption instead of Tasmota. If it saved working Wi-Fi, it often reappears at the same address. If not, join the NousA8TRescue-<id> network (password NousA8TAdopted — the same name and password Rescue itself will keep using later) and open http://192.168.4.1 instead.
  • Adoption's own page (in German) checks itself and shows live progress across four checks: Hardware, Software, Vorbereitung (preparation), Installation. Once the first three pass, it shows Rescue's Wi-Fi AP name/password and two buttons.
  • If Tasmota already had working station Wi-Fi configured and reachable, Adoption carries that same, already-validated network straight into Rescue — it comes up already connected, with no onboarding AP needed at all. The AP above remains as a fallback regardless.
  • Click Tasmota überschreiben ("Overwrite Tasmota") to proceed. The device restarts into Rescue.
Point of no returnClicking Tasmota überschreiben restarts the device into Rescue. The original Tasmota firmware is gone after this.
If it fails insteadAdoption checks the device before writing anything permanent, and never overwrites itself. If a check fails, its page shows what failed and offers a single button instead: Tasmota wiederherstellen ("Restore Tasmota") — this writes nothing; it just switches the device back to the still-genuine factory Tasmota safeboot and restarts into it. From there, use that page's own "Firmware Upgrade" to upload a real tasmota32.bin (get it from NOUS) and put the plug back exactly as it was.
2

Rescue is live

Already verified as part of confirming Adoption. Main — where the App goes — is still intentionally empty.
  • If Tasmota's station Wi-Fi carried over, Rescue is already on your network — check your router's device list or try the same address the plug had before.
  • Otherwise, join NousA8TRescue-<id> with password NousA8TAdopted (the fixed default from the quick reference above).
  • Open Rescue's address in a browser. Its own page shows device status directly — this is where Stage 3 happens too.
3

Install Charge Guard

Writes the App into Main, from Rescue's own upload form. Rescue itself stays protected underneath it.
  • On Rescue's page, open the firmware update section and choose NousA8TChargeGuard.bin.
  • Start the upload. Rescue reads the file back from flash to confirm it wrote correctly before offering to start it.
  • Commit from the same page. The App takes over the network connection next, so Rescue's own page will stop responding here — that's the expected sign it worked.
DoneThe plug is now running Charge Guard, with Rescue sitting underneath ready for the next update.

Never run idf.py flash or a raw esptool write against an adopted device — only Rescue's own web interface keeps writes inside the partitions they're supposed to touch.
